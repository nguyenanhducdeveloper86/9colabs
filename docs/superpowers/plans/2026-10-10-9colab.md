# 9colab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `9colab`, a multi-account CLI wrapper around `google-colab-cli` with account isolation, round-robin (B) and fill-first (C) selection, automatic HTTP 412 failover, live session routing, and parallel multi-account execution.

**Architecture:** `9colab` isolates each Google account in `~/.9colab/accounts/<name>` by setting `HOME` when invoking `colab`. Pure selection and failover logic lives in `src/ninecolab/pick.py`, profile/token/API helpers live in `src/ninecolab/accounts.py`, and full 26-command `google-colab-cli` routing lives in `src/ninecolab/cli.py`.

**Tech Stack:** Python >= 3.10 standard library only (`argparse`, `concurrent.futures`, `json`, `os`, `shutil`, `subprocess`, `urllib.request`, `unittest`).

**Spec:** `docs/superpowers/specs/2026-10-10-9colab-design.md`

## Global Constraints

- Wrap `colab` (`google-colab-cli` 0.7.4). Do not patch `colab_cli` files.
- Use Python standard library only. Zero external runtime dependencies.
- Store profiles in `~/.9colab/accounts/<name>` with mode `0700`. Never store credentials in the repository.
- Keep 100% of `google-colab-cli` commands and flags working.
- Default selection mode is `round-robin` (B). Optional mode is `fill-first` (C).

## Review Focus

- User script failure vs VM allocation refusal: `9colab run` must fail over only on VM allocation refusal (`Allocation refused (precondition failed)` or `Backend rejected accelerator`), never when the user script itself exits with a non-zero code.
- Ambiguous session lookup: when two accounts own a session with the same name, or when `-s` is omitted and more than one session is active across accounts, `resolve_session_owner` must raise an error that asks for `-a <account>` or `-s <session>`.
- Expired cooldown recovery: an account whose `cooldown_until` timestamp is `<= now` must be eligible again without manual state editing.
- Invalid account names: names with `/`, `..`, or whitespace must be rejected before creating directories.
- Existing `~/.config/colab-cli/token.json`: users who already logged in with `colab` need `9colab account import <name>` so they do not have to re-authenticate.
